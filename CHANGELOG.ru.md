## [Unreleased]

- `github-agent-cli` 1.2.1 опубликован на PyPI (2026-10-30). Шесть README несут бейдж PyPI и

## [1.2.1] - 2026-10-30

### Изменено

- Дистрибутив на PyPI — **`github-agent-cli`**: имена `github-agent` (2.4.9, чужой MCP-агент) и
  `ghagent` (0.0.1, чужой GitHub-обозреватель) уже заняты. Проект, консольная команда `ghagent`,
  библиотечный пакет `ghalib` и вывод `--version` (`github-agent X.Y.Z`) сохраняют свои имена;
  меняется только имя дистрибутива, поэтому установка:
  `uv tool install github-agent-cli`, `pipx install github-agent-cli`,
  `pip install github-agent-cli` и `pip install "github-agent-cli[png]"`. Обновлены все README,
  `AGENTS.md`, страницы docs и вики, примеры; колесо и sdist теперь `github_agent_cli-X.Y.Z-*`.
- В `pyproject.toml` записано, почему дистрибутив и продукт называются по-разному, а
  `docs/PACKAGING.md` объясняет четыре имени, с которыми встречается пользователь (дистрибутив,
  консольная команда, библиотека, репозиторий), с доказательством каждого.

### Исправлено

- Шесть README явно говорят, что команды пакетных менеджеров начнут работать только после первой
  публикации на PyPI: Trusted Publishing настраивает владелец, а workflow `Publish` запускается
  вручную. До этого работают колесо из последнего релиза и клон исходников — они дают ту же
  команду `ghagent`.

## [1.2.0] - 2026-10-30

### Добавлено

- Пакет PyPI `github-agent` с консольной командой `ghagent`: `pip install github-agent`,
  `pipx install github-agent` или `uv tool install github-agent`, Python 3.11+ и ни одной
  зависимости времени выполнения; необязательное дополнение `[png]` добавляет Pillow только для
  вывода PNG-баннера.
- Многократно используемое GitHub Action (`action.yml`): composite-действие ставит этот checkout
  и запускает одну команду `ghagent`, по умолчанию `audit . --min-score 80`, с входами
  `python-version`, `working-directory` и `github-token`.
- Docker-образ (`Dockerfile`): двухэтапная сборка собирает wheel из исходного дерева и ставит его
  в `python:3.13-slim`; `ENTRYPOINT ["ghagent"]`, проверяемый репозиторий — в `/repo`.
- Pre-commit-хуки (`.pre-commit-hooks.yaml`): `ghagent-doc`, `ghagent-audit`, `ghagent-privacy` и
  `ghagent-changelog`, собираемые из тегированной ревизии через `language: python`, без отдельной
  установки.
- Правило `agents.md-length`: канонический корневой `AGENTS.md` предупреждает, если он длиннее
  120 строк, с подсказкой держать его картой, а подробности выносить в `docs/`. Правило считает
  проверенный файл, а `--ignore agents.md-length` его отключает; `AGENTS.ru.md` и вложенный
  `docs/AGENTS.md` — не канонический файл и не измеряются.
- Документация разделена на `docs/RULES.md` (каталог правил, контракты файлов, ловушки платформы),
  `docs/WIKI.md`, `docs/ARCHITECTURE.md`, `docs/IMPORT.md`, `docs/PROCEDURES.md` и
  `docs/PACKAGING.md`; `AGENTS.md` теперь карта короче 120 строк со ссылками на них.
- README перестроен: сводка — первый абзац после H1, дальше бейджи и переключатель языка, а
  установка, использование и проверка — отдельные разделы.

### Изменено

- Якоря заголовков для нелатинских письменностей: `slugify` сохраняет комбинирующие знаки всех
  категорий (`Mn`, `Mc`, `Me`), а не отбрасывает пробельные, поэтому заголовок деванагари и ссылка
  на него в оглавлении совпадают. Латинские, кириллические и греческие якоря не изменились.
- `audit` ищет сводку README после пустых строк и HTML-комментариев: маркер переключателя языков
  больше не роняет `readme.summary`, а README из одного комментария — по-прежнему роняет.
- Честность установленного пакета: из wheel `selftest` завершается с кодом `2` и сообщает, что
  набор тестов есть только в исходном дереве, а `install`, `verify-install`, `uninstall` и
  `snippet` завершаются с кодом `2` и указывают на `git clone`. `PASS` не печатается, манифест
  установки не пишется, если пакета нет; из клона поведение прежнее.
- `PACK_VERSION` поднят до 1.2.0: единственный источник — `tools/ghalib/util.py`, откуда версию
  читает `pyproject.toml`.
- CI прогоняет самопроверки на Python 3.11 и 3.13, затем документы и контракты, затем собирает
  sdist и wheel и проверяет установленную консольную команду в чистом виртуальном окружении.

### Исправлено

- Консоль или перенаправленный поток Windows с не-UTF-8 кодовой страницей (cp866, cp1251,
  cp1252) падала на любой нелатинской находке, например `ghagent assets check` со стрелкой в
  подсказке: `UnicodeEncodeError: 'charmap' codec ...`. Теперь CLI переключает stdout и stderr на
  UTF-8 с обработчиком `backslashreplace`: находка печатается, код возврата не меняется, а поток,
  который переключить нельзя, остаётся как есть.
- `README.hi.md` давал 17 ошибок `md.link-anchor`, потому что вычисление якоря отбрасывало знаки
  гласных деванагари; оглавление на хинди теперь разрешается, и `ghagent doc --root .` в этом
  репозитории завершается с кодом `0`.
- README, где сразу после H1 стоит `<!-- md-i18n:switcher -->`, не проходил `readme.summary`;
  теперь правило пропускает невидимый комментарий, и `ghagent audit .` даёт этому репозиторию
  100% без ошибок.
- 39 новых самопроверок покрывают нелатинские якоря, поиск сводки после комментария, новое правило
  с фикстурами на 150 строк, 120 строк и вложенный файл, отказы в режиме wheel и кодировку
  перенаправленного потока; всего 173 проверки.

## [1.1.0] - 2026-10-24

### Добавлено

- `ghagent assets render|check|suggest` — собственные изображения репозитория: социальное превью 1280×640, отрисованное из метаданных проекта, векторный двойник для README и проверка формата, размера файла и пикселей, alt-текста и каждого упомянутого файла. Для PNG нужен Pillow; без него создаётся SVG, и отчёт прямо об этом говорит, а не делает вид, что превью готово.
- `skills/repo-images` — как выбрать и разместить баннер, социальное превью, скриншот и схему, вместе с ограничениями платформы, которые решают, годится ли изображение вообще.
- Двуязычная документация: английские файлы основные, русские копии несут суффикс `.ru.md`, включая страницы вики, которые получают отдельную группу навигации.
- 21 новая самопроверка отрисовки и проверки изображений, включая приманки: превью, спрятанное в `node_modules`, и файл больше 1 МБ.

### Изменено

- `audit` теперь оценивает баннер в README и социальное превью: репозиторий без картинки больше не проходит как полный.
- Проверка markdown предупреждает о картинках, загружаемых по незащищённому `http://`.

### Исправлено

- `wiki publish` сообщает `wiki.remote-missing` вместе с шагом платформы вместо падения на пуше, который не может создать вики-репозиторий.
- Числа в документации обновлены: 134 самопроверки, 13 команд, 11 модулей библиотеки, 15 ловушек платформы.

## [1.0.0] - 2026-10-24

### Добавлено

- `ghagent audit` — обязательные файлы, контракт README, контракт CHANGELOG и оценка гигиены; локальное дерево или удалённые метаданные через `gh api`.
- `ghagent doc` — гигиена UTF-8/BOM/CRLF, структура заголовков, таблицы, блоки кода, alerts, картинки, внутренние ссылки и якоря, согласованность оглавления, правила приватности.
- `ghagent wiki build|verify|publish|init` — вики по манифесту с `_Sidebar.md` и `_Footer.md`, переписывание ссылок под плоское пространство вики, сухой прогон публикации, сохраняющий чужие страницы.
- `ghagent changelog check|release|suggest|notes` — соответствие Keep a Changelog 2.0.0, перенос `[Unreleased]` со ссылками сравнения, черновик из conventional commits и текст релиза.
- `ghagent meta suggest|apply` — проверка описания и тем, слияние тем при записи через `PUT /repos/{owner}/{repo}/topics`.
- `ghagent install|verify-install|uninstall|snippet` — установка в каталог навыков агента с манифестом sha256, обнаружение расхождений и печать блока правил.
- `ghagent report` — один markdown-отчёт: гигиена, документы, журнал изменений, вики.
- 113 самопроверок с фикстурами на каждое правило, приманками для правил, которые должны молчать, и публикацией в песочнице на локальный bare-репозиторий.
- Пять навыков: `github-repo`, `github-wiki`, `changelog-release`, `contributing-and-community`, `import-to-agents`.

### Безопасность

- Пакет поставляется без токенов, абсолютных путей машины и личных адресов; правило приватности роняет сборку, если такое появится, а самопроверка следит за самим пакетом.
