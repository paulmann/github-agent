# Участие в проекте

Спасибо за интерес. Проект небольшой, и каждое правило здесь проверяемо: если изменение нельзя
подтвердить командой, вернувшей `0`, оно не готово. Начните с [AGENTS.md](AGENTS.md) — там карта
проекта, затем [docs/RULES.md](docs/RULES.md) — каталог правил, и
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — как устроены модули.

## Структура репозитория

| Путь | Что там |
|---|---|
| `AGENTS.md` | карта, которую агент читает первой; `AGENTS.ru.md` — её зеркало |
| `docs/RULES.md` | полный каталог правил, контракты файлов, ловушки, карта проверок |
| `docs/WIKI.md` | манифест вики, сборка, проверка, публикация |
| `docs/ARCHITECTURE.md` | модули, коды возврата, модель отчёта, доктрина тестов |
| `docs/PACKAGING.md` | PyPI, wheel и sdist, Action, Docker, pre-commit |
| `tools/ghagent.py` | точка входа CLI |
| `tools/ghalib/` | библиотека: по модулю на область |
| `tests/run_tests.py` | весь набор тестов, его запускает `ghagent selftest` |
| `reference/` | шаблоны README, AGENTS, CHANGELOG, CONTRIBUTING и вики |
| `wiki/` | исходники вики и `wiki.json` |
| `scripts/` | `build_and_check.sh` и `build_and_check.ps1` |

## Подготовка окружения

```bash
git clone https://github.com/paulmann/github-agent.git
cd github-agent
pip install -e .
ghagent --version           # github-agent 1.2.0
ghagent selftest            # должно напечатать PASS
python tests/run_tests.py   # тот же набор тестов, полный вывод
```

Нужен Python 3.11 или новее; внешних зависимостей нет. Pillow необязателен
(`pip install -e ".[png]"`) и добавляет только вывод PNG в `ghagent assets render`.

## Как добавить правило

Правило — это не строка кода, а доказательство того, что код умеет падать. Каждый pull request,
добавляющий или меняющий проверку, несёт пять частей:

1. **Реализация** в своём модуле под `tools/ghalib/`, идентификатор правила продолжает
   существующие префиксы (`doc.`, `md.`, `privacy.`, `repo.`, `readme.`, `changelog.`,
   `assets.`, `wiki.`, `meta.`, `install.`, `verify.`, `agents.`). По идентификатору правило
   ищут в логе CI.
2. **Падающая фикстура** в `tests/run_tests.py` — минимальное дерево, на котором правило обязано
   сообщить ожидаемый идентификатор с ожидаемым уровнем. Правило без падающей фикстуры не
   принимается: его существование нельзя показать.
3. **Приманка** — соседнее дерево, на котором то же правило обязано молчать. Правило, которое не
   отличает дефект от законного случая, даёт ложные `FAIL`, а они хуже отсутствия проверки.
4. **Документация** в [docs/RULES.md](docs/RULES.md): идентификатор, уровень, что проверяется и
   какая команда это печатает. Если правило меняет контракт файла — раздел контракта правится в
   том же изменении.
5. **Карта** в [AGENTS.md](AGENTS.md) — только если правило меняет то, что агент обязан делать.
   Карта намеренно короче 120 строк (`agents.md-length` предупреждает при превышении),
   подробности живут в `docs/`.

Ложный `PASS` хуже ложного `FAIL`: правило, осмотревшее ноль объектов, обязано сообщить
`coverage.skipped`, а не вернуть зелёный вердикт. К новому правилу стоит добавить два теста:
один доказывает, что находка срабатывает, второй — что число осмотренных объектов совпадает с
тем, что обещает сообщение.

## Перед pull request

Запустите все шесть команд из корня репозитория и сохраните вывод; каждая должна вернуть `0`:

```bash
ghagent selftest
ghagent doc --root .
ghagent audit .
ghagent changelog check
ghagent assets check
ghagent privacy --root .
```

`selftest` требует клона (`tests/` нет в wheel); при установке из wheel он по замыслу возвращает
`2`. `audit` оценивает дерево: оценка ниже 80 — предупреждение, ниже 60 — ошибка. `doc` — это
проверка документации и ссылок; не глушите через `--ignore` то, что можно исправить, а если
`--ignore` уместен, отключённые идентификаторы перечислены в поле JSON `rules_ignored`.

## Проверка пакета

Изменения, затрагивающие упаковку, точку входа, `pyproject.toml` или workflow релиза, добавляют
ещё одну команду. Она собирает sdist и wheel, запускает `twine check`, сверяет версию артефакта с
`PACK_VERSION` в `tools/ghalib/util.py`, доказывает раскладку wheel (плоские `ghagent.py` и
`ghalib/`, без пакета `tools`), доказывает отсутствие сторонних зависимостей, ставит wheel в
чистое виртуальное окружение и запускает установленный CLI:

```powershell
pwsh -NoProfile -File scripts/build_and_check.ps1
```

```bash
bash scripts/build_and_check.sh
```

При успехе печатается `PASS`, в репозиторий ничего не пишется (всё происходит во временном
каталоге). Модель упаковки описана в [docs/PACKAGING.md](docs/PACKAGING.md).

## Язык документации

Английский — канонический. Перевод несёт суффикс `.ru.md` (`README.ru.md`, `AGENTS.ru.md`,
`docs/IMPORT.ru.md`) и обновляется в том же коммите, что и оригинал: перевод, который молча
отстал, — дефект, а не пункт бэклога. Новые страницы следуют той же схеме: `NAME.md` плюс
`NAME.ru.md`. Страницы вики — тоже, и новая страница попадает в `wiki/wiki.json` тем же
изменением.

## Текст и кодировка

Файлы — UTF-8 без BOM, переводы строк LF; проза переносится около 100 символов, у блоков кода
указан язык, таблицы совпадают по числу ячеек с заголовком. Всё это проверяет
`ghagent doc --root .`, включая якоря: якорь заголовка — это заголовок в нижнем регистре, без
пунктуации, пробелы заменены дефисами.

## Коммиты и журнал изменений

Conventional Commits, одна логическая правка на коммит: `feat:`, `fix:`, `docs:`, `perf:`,
`refactor:`, `test:`, `chore:`, `security:`. Ломающее изменение помечается `!` в заголовке или
`BREAKING CHANGE:` в теле, а его масштаб относительно границы модуля объясняется в теле, а не
подразумевается. Заголовок — в повелительном наклонении, после двоеточия строчная буква.

Запись в журнал пишет человек: `ghagent changelog suggest --since v1.1.0` черновиком раскладывает
заголовки коммитов по разделам Keep a Changelog, а что из этого увидит пользователь, решает
ревьюер. Перед тегом `ghagent changelog check` должен проходить.

## Зависимости

Внешних зависимостей нет. Пакет ставится копированием каталога и обязан работать на голом
Python 3.11 без доступа к сети — ради этого его и берут. Pillow остаётся необязательным
дополнением и влияет только на вывод PNG. `scripts/build_and_check.ps1` валит сборку, если wheel
объявляет `Requires-Dist` без пометки extra.

## Безопасность

Не коммитьте токены, пароли, закрытые ключи, личные адреса и абсолютные пути машины.
`ghagent privacy --root .` и та же проверка внутри `ghagent doc` останавливают сборку, если такое
появилось; допустимые заглушки — `<token>`, `<path>`, `example.com` и
`user@users.noreply.github.com`. Об уязвимости сообщайте так, как описано в [SECURITY.md](SECURITY.md),
приватно, а не публичной задачей. Если секрет всё же закоммичен, сначала смените его, потом
чистите историю: удаление файла новым коммитом его не убирает.

## Сообщение об ошибке

Приложите версию (`ghagent --version`), версию Python, операционную систему, команду целиком, код
возврата и вывод `--json`. Для проблемы конкретного репозитория — минимальный фрагмент дерева,
который её воспроизводит, без секретов.
