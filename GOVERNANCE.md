# Управление проектом

## Роли

| Роль | Кто | Права |
|---|---|---|
| Сопровождающий | владелец репозитория | слияние, релизы, публикация вики, метаданные |
| Участник | любой автор pull request | изменение кода и документации через pull request |
| Пользователь | любой читатель | issues, обсуждения |

## Как принимается изменение

1. Issue описывает проблему: что не так, чем подтверждается, что должно измениться.
2. Pull request содержит правку, фикстуру (если меняется правило проверки) и запись в
   [CHANGELOG.md](CHANGELOG.md) в разделе `[Unreleased]`.
3. Прогон `python tests/run_tests.py`, `ghagent doc --root .`, `ghagent audit .` — зелёный.
4. Сопровождающий сливает; при споре решает замер, а не мнение.

## Как выпускается версия

Семантическое версионирование: `fix` — патч, `feat` — минор, ломающее изменение —
мажор. Порядок:

```bash
python tools/ghagent.py changelog release <версия> --write
python tools/ghagent.py changelog check
git tag -a v<версия> -m "v<версия>"
python tools/ghagent.py changelog notes <версия> > release-body.md
```

## Чего в проекте нет

- Скрытых каналов принятия решений: все изменения видны в истории репозитория.
- Зависимостей, которые нужно устанавливать: пакет работает на стандартной библиотеке.
- Отдельного «комитета»: проект ведётся одним сопровождающим, и это записано, чтобы не
  создавать ложного впечатления коллективного управления.
