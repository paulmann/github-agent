# AGENTS.md — репозиторий и вики GitHub под управлением агента

Инструкция для агента, который ведёт репозиторий GitHub и его вики: проверяет гигиену, пишет
README и AGENTS.md, следит за CHANGELOG и файлами сообщества, рисует изображения, собирает и
публикует вики, проверяет ссылки и якоря. Python 3.11+, только стандартная библиотека; Pillow
необязателен и добавляет лишь вывод PNG. Этот файл — карта: подробности в документах по ссылкам
ниже.

## Что делает пакет

Большинство репозиториев проваливаются не на коде, а на документации: нет раздела установки,
CHANGELOG без дат, вики из несвязанных страниц, сломанная картинка. Ничего не падает, потому что
`git push` проходит, а проверки нет. Пакет превращает повторяющиеся работы в одну команду на
каждую: `0` — чисто, `1` — есть ошибки, `2` — ошибка вызова или окружения.

## Установка

```bash
uv tool install github-agent            # рекомендуется: изолированный CLI
pipx install github-agent               # альтернатива
pip install github-agent                # Python 3.11+
pip install "github-agent[png]"         # необязательный Pillow: только PNG
ghagent --version                       # github-agent 1.2.0
```

Wheel содержит только CLI. Пакет — `skills/`, `tools/`, `tests/`, `reference/`, `wiki/`,
`docs/` и корневые документы — ставится в корень навыков агента из клона; `selftest` и `install`
из wheel отказываются работать. Профили, `--target`, обновление и удаление:
[docs/IMPORT.md](docs/IMPORT.md).

```bash
git clone https://github.com/paulmann/github-agent.git
python tools/ghagent.py install --profile harness --write     # ~/.dsh/skills
python tools/ghagent.py install --profile autoclaw --write    # ~/.pi/agent/skills
```

## Одна команда на задачу

| Задача | Команда | Что проверяется |
|---|---|---|
| Гигиена репозитория | `ghagent audit .` | обязательные файлы, контракты README и CHANGELOG, оценка |
| Документы | `ghagent doc --root .` | BOM/CRLF, заголовки, таблицы, ссылки, якоря, TOC, длина AGENTS |
| Секреты и приватность | `ghagent privacy --root .` | токены, пути машины, личные адреса |
| Изображения | `ghagent assets render\|check\|suggest` | баннер, соцпревью, размеры, ссылки |
| Вики | `ghagent wiki build\|verify\|publish` | манифест, сайдбар, футер, переписывание ссылок, публикация |
| Журнал и релиз | `ghagent changelog check\|release\|suggest\|notes` | Keep a Changelog, релиз, заметки |
| Метаданные | `ghagent meta suggest\|apply` | описание, темы, домашняя страница |

Все проверки принимают `--json` и печатают `file:line` плюс идентификатор правила; `report`
собирает их в один файл.

## Правила, которые нельзя нарушать

1. **Только измеренные числа.** У каждой цифры есть источник: команда, файл, ответ API.
2. **Никаких секретов, путей машины и личных адресов** в дереве, включая примеры.
3. **Один H1 на документ и язык у каждого блока кода.**
4. **Вики — плоское пространство имён:** без `.md` в ссылках, картинки по абсолютному URL,
   сайдбар и футер обязательны.
5. **Публикация только по явному флагу.** `wiki publish` без `--push` — сухой прогон; `--prune`
   удаляет страницы на сервере и является решением человека.
6. **CHANGELOG по Keep a Changelog 2.0.0:** даты ISO, новые версии сверху, ссылки сравнения.
7. **AGENTS.md — карта короче 120 строк** (`agents.md-length` предупреждает при превышении),
   подробности в `docs/`.
8. **Ложный PASS хуже ложного FAIL.** Правило, осмотревшее ноль объектов, сообщает
   `coverage.skipped`; пустой успех — дефект.
9. **Английский канонический.** `NAME.ru.md` повторяет `NAME.md`; коммиты подписывает владелец.

## Проверка

```bash
ghagent selftest          # только из клона: tests/ нет в wheel
ghagent doc --root .
ghagent audit .
ghagent changelog check
ghagent assets check
ghagent privacy --root .
```

Все шесть команд должны вернуть `0`. `1` — находки уровня ошибки, печатаются с `file:line`; `2` —
неверный путь, отсутствующий файл или команда, которой нужен исходный код.

## Чего не делать

- Публиковать вики без `wiki verify` и без чтения сухого прогона.
- Удалять страницы вики на сервере ради порядка; `--prune` — решение, а не привычка.
- Переписывать CHANGELOG из журнала коммитов; `changelog suggest` готовит черновик, пишет человек.
- Добавлять внешнюю зависимость, править только `.ru.md` и оставлять английский оригинал.
- Подписывать коммит именем агента и заявлять число, которого нет в README.

